# 22. Universal Framework Convergence Plan

## 1. Context & Objectives

As of 2026-05-20, the ESP-Hosted-MCU framework has achieved **Milestone C (Core Isolation)**. The `host/core/` directory is 100% platform-independent and passes all isolation checks. However, the system still faces challenges in the API and Port layers that prevent it from being a truly "Universal Framework."

This document outlines the convergence path to **Milestone D (Full Independence)**, where the host code can be ported to any MCU/RTOS by implementing ONLY the contracts defined in `h_port_contract.h`.

### Key Objectives
*   **Decouple the API Layer**: Remove mandatory dependencies on ESP-IDF specific headers (e.g., `esp_wifi_remote.h`) in the generic API path.
*   **Promote Universal APIs**: Shift the validation focus from `esp_wifi_remote_*` to the universal `h_wifi_*` APIs.
*   **Harden the Control Path**: Ensure the core control plane (Serial IF) relies solely on contracts, eliminating legacy `transport_pserial` bridges.

## 2. Strategic Actions

### 2.1 API Layer Refactoring
The current `host/api/` contains bridge code that attempts to mimic the ESP-IDF Wi-Fi driver. While useful for ESP-IDF users, it introduces headers that don't exist on other platforms (e.g., STM32, Zephyr).
*   **Action**: Gate all ESP-specific header inclusions (like `esp_wifi_remote.h`) with `#ifdef ESP_PLATFORM`.
*   **Action**: Ensure `esp_hosted_api.c` can compile on non-ESP platforms by using internal `h_err_t` mapping.

### 2.2 Universal Validation
The `examples/host_framework_validation` example currently uses legacy `esp_` APIs.
*   **Action**: Refactor the validation example to use `h_wifi_api.h` and `h_wifi_types.h`.
*   **Benefit**: This proves the core and its contract-based port are sufficient to run the system without any legacy ESP-IDF compatibility shims.

### 2.3 Contract-Based Control Plane
The `h_serial_if.c` file is the bridge between RPC and the physical transport.
*   **Action**: Explicitly remove any `extern` declarations pointing to the legacy `transport_pserial` layer.
*   **Action**: Use the `g_h_transport` contract for all control-plane packet transmissions.

## 3. Implementation Roadmap (Final Convergence)

| Step | Task | Target Milestone |
|:---:|---|:---:|
| 1 | Gate legacy headers (`esp_wifi_remote.h`) | Milestone D |
| 2 | Refactor validation example to `h_` APIs | Milestone D |
| 3 | Remove legacy `transport_pserial` externs from Core | Milestone D |
| 4 | Consolidate `host/port/esp-idf/` as the single source for ESP port | Milestone D+ |

## 4. Verification

Success will be measured by:
1.  **Zero Build Failures**: CI building the validation example for ESP32C6 without the `esp_wifi_remote.h` header error.
2.  **100% Core Isolation**: `scripts/check_core_isolation.sh` remaining clean.
3.  **Mock Success**: `scripts/run_linux_mock_tests.sh` passing all 28+ tests with ASAN/TSAN enabled.
4.  **Hardware Parity**: The universal `h_` APIs providing the same functional coverage as the legacy `esp_` APIs on real hardware.
