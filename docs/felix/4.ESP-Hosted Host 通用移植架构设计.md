# ESP-Hosted Host 通用移植架构设计

> **本文档性质声明**
>
> 本文档是 **重构方向性大纲**，用于分析移植重构的目标、难点、方案可行性以及高层架构设计。
>
> - **不负责**具体的接口签名、数据结构设计、线程模型选择等实现细节
> - **不负责**代码级实施步骤（详见后续的 Implementation Plan）
> - **负责**指明架构方向、识别关键障碍、定义分层边界、评估方案可行性
>
> 具体实现细节（如 Wi-Fi 数据结构的具体字段、线程模型的最终选择、缓冲区所有权策略等）将在编码阶段通过实施计划逐步细化和验证。

## 目标

将 ESP-Hosted 的 host 端重构为**完全平台无关**的架构，使任何 MCU/RTOS 只需实现一组移植接口即可运行 Wi-Fi 控制和数据路径功能。

## 设计原则

1. **核心层零平台依赖**：`host/core/` 只依赖标准 C 库和移植接口头文件
2. **移植接口即契约**：`host/port/include/` 定义核心层所需的全部能力，平台适配者只需实现这些接口
3. **不回头兼容 ESP-IDF 作为特权平台**：ESP-IDF 只是众多 port 中的一个
4. **第一阶段最小功能集**：Wi-Fi 控制（Station/AP/Scan）+ 数据路径 + 基础事件通知

## 现状分析

### 已有的好基础
- `esp_hosted_os_abstraction.h` 定义了 `hosted_osi_funcs_t` 函数指针表，已抽象内存、线程、队列、互斥锁、信号量、定时器、GPIO、总线、日志等
- 有明确的 `host/port/` 目录结构

### 阻碍移植的关键问题
1. **类型泄漏**：核心代码和公共头文件使用 `esp_err_t`、`esp_event_base_t`、`esp_mac_type_t`、`esp_wifi_types.h` 等 ESP-IDF 特有类型
2. **Wi-Fi 类型系统耦合**：`host/api/src/esp_wifi_weak.c` 返回 `esp_err_t` 的函数 73 个，使用 `wifi_init_config_t`、`wifi_config_t`、`wifi_ap_record_t`、`wifi_scan_config_t`、`wifi_mode_t`、`wifi_bandwidth_t`、`wifi_ps_type_t`、`wifi_interface_t` 等约 44 种 ESP-IDF Wi-Fi 类型。这些是公共 API 的入参/返回值，必须定义平台无关的替代类型。
3. **私有 TLV 握手协议耦合**：`transport_drv.c` 包含 `esp_private/wifi.h`，依赖 `struct esp_priv_event` 和 `ESP_PRIV_EVENT_INIT`、`ESP_PRIV_CAPABILITY`、`ESP_PRIV_FIRMWARE_CHIP_ID` 等 15+ 个宏。这是 slave 上电后与 host 的能力协商协议，属于传输层核心逻辑，不能简单删除。
4. **日志宏泄漏**：核心代码直接使用 `ESP_LOGI`/`ESP_LOGE` 等 ESP-IDF 日志宏
5. **头文件依赖**：`esp_hosted_os_abstraction.h` 直接 `#include "esp_event_base.h"`
6. **配置系统耦合**：`port_esp_hosted_host_config.h` 大量依赖 `sdkconfig.h`
7. **初始化方式不可移植**：`port_esp_hosted_host_init.c` 使用 GCC 扩展 `__attribute__((constructor))`，在 Zephyr 或裸机上无法工作。需要显式 `h_hosted_init()` 入口。
8. **DMA 内存分配绕过 OSAL**：`host/drivers/transport/transport_util.c` 直接调用 `heap_caps_malloc()`，绕过了 `_h_malloc_align` 抽象。
9. **OSAL 接口不完整**：现有 `hosted_osi_funcs_t` 已定义 `_h_malloc_align`、`_h_free_align`、`_h_post_semaphore_from_isr`、`_h_queue_msg_waiting`、`_h_reset_queue`、`_h_blocking_delay`、`_h_realloc`，文档初版 `h_osal.h` 未纳入。

## 架构设计

### 目录结构

```
host/
  core/                          ← 平台无关核心层
    include/
      h_public/                  ← 对外公共 API（应用可直接 include）
        h_wifi_api.h             ← Wi-Fi 控制 API，暴露第一阶段最小接口集
        h_wifi_types.h           ← 平台无关 Wi-Fi 类型（h_wifi_init_config_t, h_wifi_config_t 等）
        h_event.h                ← 事件类型定义 + 应用级事件注册/注销接口
        h_types.h                ← 平台无关基础类型 (h_err_t, h_mac_addr_t 等)
      h_internal/                ← 核心层内部头文件（应用不应直接 include）
        h_rpc_core.h
        h_transport.h
        h_serial_if.h
        h_event_post.h           ← 核心层内部使用的事件发布接口（h_event_post）
        h_priv_event.h           ← TLV 握手协议定义（替代 esp_private/wifi.h）
    src/
      h_rpc_core.c               ← RPC 请求/响应/事件核心
      h_rpc_wrap.c               ← Wi-Fi RPC 包装器
      h_transport_drv.c          ← 传输层驱动（不含 ESP-IDF 依赖）
      h_transport_util.c         ← 传输工具函数（DMA 内存分配等）
      h_serial_if.c              ← 串行接口
      h_event.c                  ← 事件分发器
      h_api.c                    ← 公共 API 实现

  port/
    include/                     ← 移植接口定义（核心层唯一依赖的平台头文件）
      h_port_contract.h           ← 合约结构体定义 (h_osal_contract_t + h_event_contract_t + h_transport_contract_t)
      h_wrapper.h                 ← 核心层调用 macro 封装（#define h_malloc(sz) g_h_osal.malloc(sz)）
      h_config.h                  ← 编译时配置接口
      h_test_only.h               ← 测试暴露函数签名
    <platform>/                  ← 具体平台实现
      esp-idf/                   ← ESP-IDF 适配
        port_init.c              ← 显式 h_hosted_init() 实现
        tools/                   ← ESP-IDF 专属诊断工具
          stats.c
          cli.c
      freertos/                  ← 通用 FreeRTOS 适配
      zephyr/                    ← Zephyr RTOS 适配
      baremetal/                 ← 裸机适配
      linux/                     ← Linux mock（用于测试）
```

### 核心层设计

#### 1. 平台无关类型系统 (`h_types.h` + `h_wifi_types.h`)

替换所有 ESP-IDF 特有类型。核心类型放在 `h_types.h`，Wi-Fi 专用类型放在 `h_wifi_types.h`（公共头文件，应用层可直接 include）：

```c
/* h_types.h */
typedef int h_err_t;
#define H_OK     0
#define H_FAIL  -1
#define H_ERR_INVALID_ARG  -2
#define H_ERR_NO_MEM       -3
#define H_ERR_TIMEOUT      -4

typedef uint8_t h_mac_addr_t[6];

typedef enum {
    H_WIFI_MODE_NULL = 0,
    H_WIFI_MODE_STA,
    H_WIFI_MODE_AP,
    H_WIFI_MODE_APSTA,
} h_wifi_mode_t;

typedef enum {
    H_EVENT_WIFI = 0,
    H_EVENT_IP,
    H_EVENT_HOSTED,
} h_event_base_t;
```

**Wi-Fi 类型策略（第一阶段最小集合）**：

Phase 1 必须定义以下平台无关类型，以替代 ESP-IDF 的 `esp_wifi_types.h`：

| ESP-IDF 类型 | 平台无关替代 | 用途 |
|-------------|------------|------|
| `wifi_init_config_t` | `h_wifi_init_config_t` | `h_wifi_init()` 入参 |
| `wifi_config_t` | `h_wifi_config_t` | `h_wifi_set_config()` / `h_wifi_get_config()` 入参 |
| `wifi_ap_record_t` | `h_wifi_ap_record_t` | Scan 结果返回值 |
| `wifi_scan_config_t` | `h_wifi_scan_config_t` | `h_wifi_scan_start()` 入参 |
| `wifi_mode_t` | `h_wifi_mode_t` | 已定义 |
| `wifi_bandwidth_t` | `h_wifi_bandwidth_t` | `h_wifi_set_bandwidth()` |
| `wifi_ps_type_t` | `h_wifi_ps_type_t` | `h_wifi_set_ps()` |
| `wifi_interface_t` | `h_wifi_interface_t` | 几乎所有 Wi-Fi API 的第一个参数 |
| `wifi_country_t` | `h_wifi_country_t` | `h_wifi_set_country()` |
| `wifi_sta_list_t` | `h_wifi_sta_list_t` | `h_wifi_ap_get_sta_list()` |

> **决策原则**：这些结构体的字段与 ESP-IDF 的 `wifi_*` 类型一一对应，但由核心层拥有定义权。protobuf RPC 层负责将 `h_wifi_*` 类型与 protobuf 消息互转。对于 ESP-IDF port，可在 port 层提供 `h_wifi_types.h` → `esp_wifi_types.h` 的零拷贝或浅拷贝映射适配器，避免字段复制开销。

#### 2. Port 合约定义 (vtable 模式)

> **设计决策**：核心层通过 3 个函数指针结构体（vtable）访问平台能力。移植者创建 3 个 `const` global 实例填入平台 API，核心层通过 wrapper 宏零开销访问。每个子系统独立的 vtable 意味着实现、测试、替换互不耦合——单独写 OSAL 不需要碰 transport，mock 测试只需要换一个 global。

##### 2.1 合约结构体定义 (`h_port_contract.h`)

```c
/* ── OSAL 合约：内存、线程、队列、互斥锁、信号量、定时器、日志 ── */
typedef struct {
    /* 内存 */
    void* (*malloc)(size_t size);
    void* (*calloc)(size_t n, size_t size);
    void* (*realloc)(void *mem, size_t newsize);
    void  (*free)(void *ptr);
    void* (*memcpy)(void *dst, const void *src, size_t n);
    void* (*memset)(void *s, int c, size_t n);
    void* (*malloc_align)(size_t size, size_t align);
    void  (*free_align)(void *ptr);

    /* 线程 */
    int (*thread_create)(const char *name, uint32_t prio, uint32_t stack,
                         void (*fn)(void*), void *arg, h_thread_t *out);
    int (*thread_delete)(h_thread_t thread);

    /* 互斥锁 */
    int (*mutex_create)(h_mutex_t *out);
    int (*mutex_lock)(h_mutex_t m, int32_t timeout_ms);
    int (*mutex_unlock)(h_mutex_t m);
    int (*mutex_delete)(h_mutex_t m);

    /* 队列 */
    int (*queue_create)(uint32_t count, uint32_t item_size, h_queue_t *out);
    int (*queue_send)(h_queue_t q, const void *item, int32_t timeout_ms);
    int (*queue_recv)(h_queue_t q, void *item, int32_t timeout_ms);
    int (*queue_msg_waiting)(h_queue_t q);
    int (*queue_reset)(h_queue_t q);
    int (*queue_delete)(h_queue_t q);

    /* 信号量 */
    int (*sem_create)(uint32_t max, uint32_t init, h_semaphore_t *out);
    int (*sem_take)(h_semaphore_t sem, int32_t timeout_ms);
    int (*sem_give)(h_semaphore_t sem);
    int (*sem_give_from_isr)(h_semaphore_t sem, void *isr_ctx);
    int (*sem_delete)(h_semaphore_t sem);

    /* 中断上下文 */
    void (*enter_critical)(void);
    void (*exit_critical)(void);

    /* 定时器 */
    int (*timer_create)(const char *name, h_timer_t *out);
    int (*timer_start)(h_timer_t t, uint32_t period_ms, bool periodic,
                       void (*cb)(void*), void *arg);
    int (*timer_stop)(h_timer_t t);
    int (*timer_delete)(h_timer_t t);
    uint64_t (*get_time_ms)(void);

    /* 时间/延迟 */
    void (*msleep)(uint32_t ms);
    void (*usleep)(uint32_t us);
    void (*blocking_delay)(unsigned int iterations);

    /* 日志 */
    void (*log_write)(int level, const char *tag, const char *fmt, ...);
} h_osal_contract_t;

/* ── Event 合约：事件系统 ── */
typedef struct {
    int (*register_handler)(h_event_base_t base, int32_t event_id,
                            h_event_handler_t handler, void *user_ctx);
    int (*unregister_handler)(h_event_base_t base, int32_t event_id,
                              h_event_handler_t handler);
    int (*post)(h_event_base_t base, int32_t event_id,
                void *event_data, size_t event_data_size);
} h_event_contract_t;

/* ── Transport HAL 合约：SPI / SDIO / UART / GPIO / netif ── */
typedef struct {
    /* 总线 */
    int (*init)(void **out_handle);
    int (*deinit)(void *handle);

    /* SPI */
    int (*spi_transfer)(void *handle, void *transfer_ctx);

    /* SDIO */
    int (*sdio_card_init)(void *handle, bool show_config);
    int (*sdio_read_reg)(void *handle, uint32_t reg, uint8_t *data, uint16_t size, bool lock);
    int (*sdio_write_reg)(void *handle, uint32_t reg, uint8_t *data, uint16_t size, bool lock);
    int (*sdio_read_block)(void *handle, uint32_t reg, uint8_t *data, uint16_t size, bool lock);
    int (*sdio_write_block)(void *handle, uint32_t reg, uint8_t *data, uint16_t size, bool lock);
    int (*sdio_wait_intr)(void *handle, uint32_t timeout_ms);

    /* UART */
    int (*uart_read)(void *handle, uint8_t *data, uint16_t size);
    int (*uart_write)(void *handle, uint8_t *data, uint16_t size);
    int (*uart_flush)(void *handle);

    /* GPIO */
    int (*gpio_config)(uint32_t pin, uint32_t mode);
    int (*gpio_set_intr)(uint32_t pin, uint32_t intr_type, void (*isr)(void*), void *arg);
    int (*gpio_clear_intr)(uint32_t pin);
    int (*gpio_read)(uint32_t pin);
    int (*gpio_write)(uint32_t pin, uint32_t value);

    /* netif */
    int (*netif_create)(uint8_t if_type, uint8_t if_num);
    int (*netif_destroy)(uint8_t if_type, uint8_t if_num);
} h_transport_contract_t;
```

> **设计权衡——为何 Transport 合约未按传输方式拆分**：
> 
> `h_transport_contract_t` 包含了 SPI/SDIO/UART/GPIO/netif 共 ~20 个函数指针。文档3 §9.4 建议"函数指针太多时拆成多个小 vtable"，但在 ESP-Hosted 的场景中，**一个 port 通常只支持一种传输方式**（SPI 或 SDIO 或 UART），未使用的传输函数指针置 NULL 即可。
> 
> 拆分为 `h_spi_transport_t` / `h_sdio_transport_t` / `h_uart_transport_t` 确实可以消除 NULL 填充，但会带来新的复杂度：
> - 核心层需要 `#ifdef H_TRANSPORT_SPI` 分支来调用不同的 vtable 类型
> - 传输切换（编译期或运行时）的代码路径增多
> - 测试时需要 mock 多套不同的结构体签名
> 
> **决策**：保持统一的 `h_transport_contract_t`，用 NULL 表达"不支持该传输"。移植检查清单 §2.4 会验证"目标传输的函数指针非 NULL"，确保不会调用到 NULL。如果未来需要同时支持多种传输（如 SPI + UART fallback），再考虑拆分。

> **注意点**：SPI-HD 专用函数（`spi_hd_read_reg`、`spi_hd_write_reg`、`spi_hd_read_dma`、`spi_hd_write_dma`、`spi_hd_set_data_lines`、`spi_hd_send_cmd9`）属于具体 port 实现细节，不在通用合约中定义，在对应 port 的私有头文件中声明。SPI-HD port 需额外提供一个结构体挂载到其 transport init 上下文中。

##### 2.3 移植者填充示例

**所有移植工作就是创建 3 个 `const` global 实例。** 每个子系统独立一个 `.c` 文件：

```c
// ── port/esp-idf/h_osal.c ──
#include "h_port_contract.h"
#include <freertos/task.h>
#include <freertos/semphr.h>

const h_osal_contract_t g_h_osal = {
```

##### 2.5 安全防护设计

文档3 §5 提出了跨平台代码的 4 项安全防护要求。以下在 ESP-Hosted 场景中的具体落地方式：

**（1）vtable NULL 指针防护——三层防御**

```c
// 第一层：编译期断言——用于全局静态 vtable 定义处
// 在 h_port_contract.h 中标注每个指针的必需/可选属性
#define H_VTABLE_REQUIRED 1
#define H_VTABLE_OPTIONAL 0

// 用法示例：在定义 vtable 实例时，用 _Static_assert 确保关键指针已赋值
// 注意：_Static_assert 要求编译期常量，只能用于全局静态定义处
_Static_assert((const void *)&g_h_osal.malloc != NULL, "malloc must be implemented");
_Static_assert((const void *)&g_h_osal.free != NULL, "free must be implemented");
// 对于可选功能（如 stats_dump），不强制断言——由运行时检查处理

// 第二层：启动时校验——h_hosted_init() 内部调用
static h_err_t h_validate_contracts(void) {
    // OSAL 必须实现的核心函数
    if (!g_h_osal.malloc || !g_h_osal.free || !g_h_osal.mutex_create ||
        !g_h_osal.queue_create || !g_h_osal.sem_create || !g_h_osal.thread_create) {
        H_LOGE("PORT", "OSAL contract missing required functions");
        return H_ERR_INVAL;
    }
    // Event 必须实现
    if (!g_h_event.register_handler || !g_h_event.post) {
        H_LOGE("PORT", "Event contract missing required functions");
        return H_ERR_INVAL;
    }
    // Transport 根据 H_TRANSPORT_IN_USE 校验对应函数
    #if H_TRANSPORT_IN_USE == H_TRANSPORT_SPI
        if (!g_h_transport.init || !g_h_transport.spi_transfer) {
            H_LOGE("PORT", "SPI transport contract missing required functions");
            return H_ERR_INVAL;
        }
    #elif H_TRANSPORT_IN_USE == H_TRANSPORT_SDIO
        if (!g_h_transport.init || !g_h_transport.sdio_read_block) {
            H_LOGE("PORT", "SDIO transport contract missing required functions");
            return H_ERR_INVAL;
        }
    #endif
    H_LOGI("PORT", "All required vtable slots filled");
    return H_OK;
}

// 第三层：运行时安全调用——用于可选功能
#define H_VTABLE_CALL(ops, func, ...) \
    ((ops)->func ? (ops)->func(__VA_ARGS__) : H_ERR_NOTSUP)
```

**（2）错误码转换约定**

每个 port 的适配层负责将平台原生错误码翻译为统一的 `h_err_t`：

| 平台 | 原始返回值 | 转换规则 | `h_err_t` |
|------|-----------|---------|:---------:|
| FreeRTOS | `pdTRUE` / `pdPASS` | 直接映射 | `H_OK` |
| FreeRTOS | `pdFALSE` / `errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY` | 按语义映射 | `H_ERR_TIMEOUT` / `H_ERR_NO_MEM` |
| Zephyr | `0` | 直接映射 | `H_OK` |
| Zephyr | `-EAGAIN` / `-ENOMEM` / `-ETIMEDOUT` | 取反后映射 | `H_ERR_TIMEOUT` / `H_ERR_NO_MEM` |
| Linux (mock) | `0` | 直接映射 | `H_OK` |
| Linux (mock) | `-errno` | 按 errno 语义映射 | `H_ERR_*` |

**禁止**：核心层直接判断 `ret == pdTRUE` 或 `ret == 0`——必须统一使用 `h_err_t`。

**（3）平台版本标识**

每个 port 在 `h_port_config.h` 中定义版本信息：

```c

```

启动时打印，便于诊断：

**（4）init/deinit 资源释放顺序**

```c
h_err_t h_hosted_init(void) {
    h_err_t err;
    
    // Step 1: 校验 contracts（fail-fast）
    H_RETURN_IF_ERR(h_validate_contracts());
    
    // Step 2: 初始化 OSAL（分配 mutex/queue/sem）
    err = h_osal_init();
    if (err != H_OK) goto cleanup_osal;
    
    // Step 3: 初始化 event 系统
    err = h_event_init();
    if (err != H_OK) goto cleanup_event;
    
    // Step 4: 初始化 transport
    err = h_transport_init();
    if (err != H_OK) goto cleanup_transport;
    
    // Step 5: 启动 RPC 核心
    err = h_rpc_core_init();
    if (err != H_OK) goto cleanup_rpc;
    
    g_hosted_initialized = true;
    return H_OK;

cleanup_rpc:
    h_transport_deinit();
cleanup_transport:
    h_event_deinit();
cleanup_event:
    h_osal_deinit();
cleanup_osal:
    return err;
}

h_err_t h_hosted_deinit(void) {
    if (!g_hosted_initialized) return H_OK;
    
    // 逆序释放——与 init 严格对称
    h_rpc_core_deinit();   // ← 最后 init 的，最先 deinit
    h_transport_deinit();
    h_event_deinit();
    h_osal_deinit();
    
    g_hosted_initialized = false;
    return H_OK;
}
```

**（5）资源泄漏防护——跨平台语义差异**

| 平台 | `mutex` 销毁前置条件 | `queue` 清空语义 | 防护策略 |
|------|---------------------|-----------------|---------|
| FreeRTOS | 必须 unlock | `xQueueReset` 丢弃所有数据 | OSAL 层 `h_mutex_delete` 内部先 unlock |
| Zephyr | `k_mutex_unlock` 后可 `k_mutex_free` | `k_msgq_purge` | OSAL 层统一封装销毁语义 |
| Linux (mock) | `pthread_mutex_unlock` | 无（用 pipe 模拟） | 适配层处理差异 |

**原则**：OSAL 层封装统一销毁语义，不让上层感知平台差异。例如 `h_mutex_delete` 内部先检查持有状态，unlock 后再 destroy。

#### 3. 私有事件协议接口 (`h_priv_event.h`)

`transport_drv.c` 依赖 `esp_private/wifi.h` 中的 `struct esp_priv_event` 和 `ESP_PRIV_*` 宏，用于 slave 上电后的能力协商（TLV 握手协议）。这是传输层核心逻辑，必须保留但去 ESP-IDF 化：

```c
typedef struct {
    uint8_t event_type;
    uint8_t *tlv_data;
    uint16_t tlv_len;
} h_priv_event_t;

#define H_PRIV_EVENT_INIT              0x01
#define H_PRIV_CAPABILITY              0x10
#define H_PRIV_CAP_EXT                 0x11

#define H_PRIV_FIRMWARE_CHIP_ESP32     0x00
#define H_PRIV_FIRMWARE_CHIP_ESP32C2   0x01
/* ... 其他芯片常量 ... */
#define H_PRIV_TEST_RAW_TP             0x30
#define H_PRIV_RX_Q_SIZE               0x40
```

#### 4. 配置接口 (`h_config.h`)

替换 `sdkconfig.h`：

```c

#define H_CONFIG_H
```

> **注意点**：当前 `rpc_req.c` / `rpc_rsp.c` 中通过 `#include "esp_idf_version.h"` 做版本条件编译。重构后该版本宏由 port 层以 `H_IDF_VERSION_MAJOR` / `H_IDF_VERSION_MINOR` 形式提供，核心层不再直接引用 ESP-IDF 版本头文件。

#### 5. 显式初始化入口

当前 `port_esp_hosted_host_init.c` 使用 `__attribute__((constructor))`，这不是标准 C，在 Zephyr 或裸机上无法工作。**重构后必须提供显式初始化函数**：

```c
/* 由应用层在 main 中显式调用 */
h_err_t h_hosted_init(void);
h_err_t h_hosted_deinit(void);
```

ESP-IDF port 可在 `h_hosted_init()` 内部继续调用 `esp_hosted_init()`，但不再依赖 GCC constructor。裸机/Zephyr port 由用户代码显式调用。

#### 6. `H_HOST_USES_STATIC_NETIF` 处理方案

当前 SPI/SDIO 驱动中存在 `#if H_HOST_USES_STATIC_NETIF` 条件编译块，内含 `esp_netif_*`、`esp_wifi_*`、`esp_event_*` 调用（共 10+ 处）。这是 ESP-IDF 平台的 netif 创建/销毁特殊逻辑。

**决策**：该逻辑已纳入 `h_transport_contract_t` 的 `netif_create` / `netif_destroy` 字段。核心层用 `#ifdef H_HOST_USES_STATIC_NETIF` 包裹相关调用，但调用的是 `h_netif_create()` / `h_netif_destroy()` 宏，而非直接调用 `esp_netif_create_default_wifi_*()`。ESP-IDF port 在填充 `g_h_transport` 时，将 `netif_create` 指向封装了 ESP-IDF netif API 的函数。

#### 7. stats.c / esp_hosted_cli.c 位置

这两个文件有最重的 ESP-IDF 依赖：
- `stats.c`：6 个 `heap_caps_*` 直接调用
- `esp_hosted_cli.c`：15 个头文件、3 个 FreeRTOS API、8+ 个 `heap_caps_*` 调用

**决策**：它们属于 ESP-IDF 专属诊断工具，**不放入 `host/core/`**。重构后移至：
- `host/port/esp-idf/tools/stats.c`
- `host/port/esp-idf/tools/cli.c`

或保留在原位但用 `#ifdef H_PORT_ESP_IDF` 守卫。CI 核心层隔离检查脚本需要排除 `host/port/` 目录。

#### 8. 线程配置参数

当前 13 个内部线程的 stack size / priority 来自 `sdkconfig.h`（如 `CONFIG_ESP_HOSTED_DFLT_TASK_STACK`）。`h_config.h` 需要以下参数：

```c
#ifndef H_DEFAULT_TASK_STACK
#define H_DEFAULT_TASK_STACK  4096
#endif
#ifndef H_DEFAULT_TASK_PRIO
#define H_DEFAULT_TASK_PRIO   5
#endif
/* 各传输专用的 stack/priority，由 h_port_config.h 覆盖 */
```

#### 9. DMA 内存分配修复

`transport_util.c:27` 直接调用 `heap_caps_malloc()`。修复方案：
- **首选**：改用 `h_malloc_align(size, align)`，由 port 层保证 DMA 能力（ESP-IDF port 内部调用 `heap_caps_malloc(..., MALLOC_CAP_DMA)`）
- **备选**：在 `h_osal_contract_t` 中增加 `h_malloc_dma(size_t size)` 专用接口

### 数据流

#### RPC 请求流（平台无关）
```
App: h_wifi_init(&cfg)
  → core/src/h_api.c
  → core/src/h_rpc_wrap.c: 构造 protobuf 请求
  → core/src/h_rpc_core.c: 分配 UID, 发送请求到 serial_if
  → core/src/h_serial_if.c: 添加 hosted header, 放入 TX queue
  → port HAL: g_h_transport.spi_transfer() (或 sdio/uart)
  → Slave
```

#### 事件流（平台无关）
```
Slave: Wi-Fi 事件
  → Host Transport: 收到带 ESP_SERIAL_IF 的帧
  → core/src/h_transport_drv.c: 解包，交给 serial_if
  → core/src/h_serial_if.c: 识别为 RPC 事件
  → core/src/h_rpc_core.c: 反序列化 protobuf 事件
  → core/src/h_event.c: 调用 h_event_post()
  → port: g_h_event 的实现 (如 Zephyr 的 k_event, FreeRTOS 的 event group)
  → App: 注册的回调被调用
```

#### 数据路径（网络帧，平台无关）
```
Slave: 网络帧
  → Host Transport: 收到带 ESP_STA_IF/ESP_AP_IF 的帧
  → core/src/h_transport_drv.c: 解包 hosted header
  → App: 通过注册的 rx callback 收到原始帧
```

## 测试策略

> **核心洞察**：`host/port/include/` 的合约接口不仅是跨平台移植的桥梁，更是**天然的 mock 注入点**。有了它，核心层 90% 的逻辑 bug 可以在 CI 上零硬件成本抓到，不再需要每次改动都烧板子调试。

### 测试金字塔

```
                    ┌─────────────────┐
                    │  Tier 3          │  PR 合并前
                    │  硬件集成测试     │  30min, 手动
                    │  (framework +    │
                    │   iperf)         │
                    ├─────────────────┤
                    │  Tier 2          │  每次 push
                    │  CI 纯软件测试    │  3min, 自动
                    │  (Linux mock)    │
                    ├─────────────────┤
                    │  Tier 1          │  每次 push
                    │  编译隔离检查     │  30s, 自动
                    └─────────────────┘
```

| Tier | 名称 | 运行环境 | 耗时 | 频率 | 硬件需求 |
|:---:|------|---------|:---:|------|:---:|
| 1 | **编译隔离检查** | `gcc` + `grep` | 30s | 每次 push | 无 |
| 2 | **CI 纯软件测试** | Linux mock port + Unity | 3min | 每次 push | 无 |
| 3 | **硬件集成测试** | 真实 ESP32-P4 + C6 板 | 30min | PR 合并前 | 一对 ESP 板 |

**修改流程与测试的对应关系**：

```
改一行代码 → 本地编译 → git push → CI 自动跑 Tier 1 + 2 → 3 分钟内出结果
                                    ↓ (通过)
               开 PR → 手动跑 Tier 3 (`host_framework_validation` → `host_framework_iperf_validation`) → 确认无功能/性能倒退 → 合并
```

### 分层测试规格

每一层抽象接口都有对应的验证手段。以下测试全部在 **Tier 2 (Linux mock)** 中自动运行：

| 层级 | 被测代码 | Mock 什么 | 验证内容 | 关键测试用例 |
|------|---------|----------|---------|------------|
| **OSAL 层** | `h_osal_contract_t` port 实现 | 无（直接测试 port 映射） | `h_malloc`/`h_mutex`/`h_queue`/`h_timer`/`h_thread` 正确性 & 线程安全性 | 并发压力测试、超时语义一致性、ISR 上下文 `h_sem_give_from_isr` |
| **Transport HAL 层** | `h_transport_contract_t` 的调用方 | mock HAL 结构体（函数指针 → 测试桩） | 核心层在每种传输模式下正确调用 init/transfer/deinit | HAL 函数调用序列验证、参数校验 |
| **Transport 核心层** | `h_transport_drv.c` | mock HAL 读写函数，注入伪造 hosted header + payload | 帧解析、接口分派、TLV 握手协议、错误恢复 | 正常握手 / 超时 / 畸形帧 / 芯片不匹配 / FW 版本不匹配 |
| **Serial IF 层** | `h_serial_if.c` | mock transport 层 | 帧类型到处理器的路由 | `ESP_SERIAL_IF`→RPC 核心、`ESP_STA_IF`→数据回调、`ESP_PRIV_IF`→TLV 解析器 |
| **RPC 核心层** | `h_rpc_core.c` | mock serial_if，直接注入 protobuf-c 字节流 | 请求/响应匹配、UID 管理、超时处理、事件反序列化 | 正常配对 / 响应超时 / 乱序到达 / 重复 UID / 内存不足 |
| **RPC Wrap 层** | `h_rpc_wrap.c` | mock rpc_core | `h_wifi_*` → protobuf 类型转换正确性 | `h_wifi_init`/`h_wifi_set_config`/`h_wifi_scan_start` 生成 protobuf 与预期一致 |
| **事件层** | `h_event.c` | mock `h_event_contract_t` 实现 | 注册/注销/分发、事件数据生命周期 | 正确回调 / 注销后不再接收 / 多 handler 顺序 / 无内存泄漏 |
| **集成测试** | 核心层全链路 | mock 完整 slave 行为 | 端到端 SoftAP 启动 → STA 连接 → TCP/UDP 数据帧收发 | `h_wifi_set_mode(AP)` → 连接事件 → 数据帧收发闭环 |

### Linux Mock Port (`host/port/linux/`)

专门为 Tier 1/2 CI 测试存在的仿真平台，不是产品级 port。

**OS 原语映射**：

| 抽象接口 | Linux mock 实现 | 说明 |
|---------|----------------|------|
| `h_thread_t` | `pthread_t` | POSIX 线程 |
| `h_mutex_t` | `pthread_mutex_t` | 可配合 TSAN 检测数据竞争 |
| `h_semaphore_t` | `sem_t` (POSIX 信号量) | 支持 `sem_post`/`sem_wait` |
| `h_queue_t` | `pipe()` 或 `socketpair()` + 读写线程 | 用文件描述符模拟消息队列 |
| `h_timer_t` | `timerfd_create()` + `epoll` | 10ms 精度 |
| `h_malloc` / `h_free` | `malloc` / `free` | 可接入 ASAN 检测内存泄漏 |
| GPIO / 传输 HAL | 可编程测试桩 | 测试用例预设"slave 响应序列" |

**关键设计点**：

- 所有 `h_*` 句柄为 `void*` 不透明指针，Linux mock 内部用 `malloc` 分配真实结构体并强制转换
- Transport HAL mock 提供"可编程响应"能力：测试用例通过注册回调或预置 FIFO 序列，控制 `_h_sdio_read_block` 等函数的返回值和数据
- ASAN/TSAN 兼容：Linux mock 使用标准 `malloc` 和 `pthread`，可直接链接 `-fsanitize=address,thread`

**测试辅助头文件** (`host/port/include/h_test_only.h`)：

```c
#ifdef H_BUILD_TESTS
/* 暴露核心层内部函数签名，供测试用例直接调用 */
h_err_t h_transport_drv_process_frame(uint8_t *frame, uint16_t len);
h_err_t h_rpc_core_dispatch(uint8_t *pb_data, uint16_t pb_len);
h_err_t h_serial_if_route_frame(uint8_t if_type, uint8_t *payload, uint16_t len);
#endif
```

### CI 工作流设计

重构后在 GitHub Actions 上运行 3 个 Job。所有 Job 均使用 `ubuntu-latest` runner，**零硬件依赖**。

```yaml
# .github/workflows/test.yml
name: host-core-test

on:
  push:
    paths:
      - 'host/core/**'
      - 'host/port/include/**'
      - 'host/port/linux/**'
      - 'common/proto/**'
  pull_request:

jobs:
  # ── Tier 1: 编译隔离检查 (30s) ──
  isolation-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check core layer is ESP-IDF free
        run: scripts/check_core_isolation.sh
      - name: Verify core compiles with zero ESP-IDF deps
        run: |
          for f in host/core/src/*.c; do
            gcc -fsyntax-only -I host/core/include/h_public \
                -I host/core/include/h_internal \
                -I host/port/include \
                -I common/proto \
                -I common/protobuf-c/protobuf-c \
                -DH_BUILD_TESTS \
                "$f"
          done

  # ── Tier 2: Linux mock 纯软件测试 (3min) ──
  linux-mock-test:
    runs-on: ubuntu-latest
    needs: isolation-check
    steps:
      - uses: actions/checkout@v4
      - name: Build test executable
        run: |
          gcc -o test_runner \
              -I host/core/include/h_public \
              -I host/core/include/h_internal \
              -I host/port/include \
              -I common/proto \
              -I common/protobuf-c/protobuf-c \
              -DH_BUILD_TESTS \
              -fsanitize=address,undefined \
              host/core/src/*.c \
              host/port/linux/src/*.c \
              tests/*.c \
              tests/unity/unity.c \
              common/protobuf-c/protobuf-c/protobuf-c.c \
              common/proto/esp_hosted_rpc.pb-c.c \
              -lpthread
      - name: Run tests
        run: ./test_runner -v
      - name: Run with ThreadSanitizer
        run: |
          gcc -o test_runner_tsan \
              -fsanitize=thread \
              host/core/src/*.c host/port/linux/src/*.c tests/*.c \
              tests/unity/unity.c \
              common/protobuf-c/protobuf-c/protobuf-c.c \
              common/proto/esp_hosted_rpc.pb-c.c \
              -lpthread
          ./test_runner_tsan -v

  # ── Tier 3 (编译部分): ESP-IDF 构建矩阵 (30min) ──
  esp-idf-build-matrix:
    runs-on: ubuntu-latest
    needs: linux-mock-test
    strategy:
      matrix:
        target: [esp32c6]
        transport: [sdio, spi, uart]
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive
      - name: Build slave (${{ matrix.target }}, ${{ matrix.transport }})
        uses: espressif/esp-idf-ci-action@v1
        with:
          esp_idf_version: v5.3
          target: ${{ matrix.target }}
          command: |
            cd slave
            idf.py -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.ci.${{ matrix.transport }}" build
```

**Job 说明**：

| Job | 做什么 | 为什么 |
|-----|--------|--------|
| `isolation-check` | `grep` 检查 core 层无 `esp_*` 引用 + 逐文件语法编译 | 防止贡献者无意中引入 ESP-IDF 依赖 |
| `linux-mock-test` | 编译所有 core 源码 → 链接 Linux mock → 运行 Unity 测试套件 → TSAN 跑第二遍 | 零硬件成本验证核心逻辑正确性 |
| `esp-idf-build-matrix` | 用 `espressif/esp-idf-ci-action` 编译 slave (esp32c6 × sdio/spi/uart) | 确认重构没有打断现有 slave 构建 |

> **注意**：`esp-idf-build-matrix` 只编译 slave（co-processor 固件），不编译 host 端——host 端的 ESP-IDF 构建在 Tier 3 硬件回归时单独验证，因为在 CI 上没有真实的 P4 工具链。

### 硬件在环分层冒烟测试

新平台 port 或核心层重大修改后，必须在真实硬件上逐层验证，确保 port 层的 GPIO 时序、DMA 配置、中断处理等硬件相关实现正确：

| 步骤 | 测试内容 | 验证目标 | 通过标准 |
|---|---|---|---|
| 1 | Slave 独立启动 | 确认 slave 固件正常 | Slave 串口输出正常启动日志 |
| 2 | SPI/SDIO/UART 物理链路 | Host 发送测试帧（如 0xAA/0x55 模式），Slave 回环 | 明文收发数据一致，无丢包/错位 |
| 3 | TLV 握手协议 | Slave 上电后 host 解析 `h_priv_event_t` | Host 正确提取 slave 芯片 ID、能力位、固件版本 |
| 4 | RPC 请求/响应 | Host 发送 `h_wifi_get_mode()` 等简单 RPC | 请求 UID 与响应 UID 匹配，返回码正确 |
| 5 | Wi-Fi 控制 | `h_wifi_set_mode(AP)` + 配置 SoftAP + 外部 STA 连接 | STA 能扫描并连接到 SoftAP，host 收到 connected 事件 |
| 6 | 数据路径 | Ping / iperf TCP / iperf UDP | Ping 延迟正常，TCP/UDP 吞吐量不低于重构前 ±5% |

> **原则**：每移植/修改一层，就在该层做验证，不堆积到集成阶段。Mock 测试用于日常开发的快速回归，硬件在环测试用于 port 完成度和发布前的最终验收。

### 硬件验收测试 (Tier 3)

Tier 1 和 Tier 2 在 CI 上自动运行，Tier 3 在 PR 合并前**手动执行**：

**设备**：ESP32-P4-Function-EV-Board（host）+ 板载 ESP32-C6（slave），SDIO 连接。

**推荐执行顺序**：Tier 3 建议按两个样例顺序执行，而不是只看单次 iperf 吞吐。

1. 先跑 `host_framework_validation`，确认 Host 通用框架的基线生命周期路径成立。
2. 再跑 `host_framework_iperf_validation`，确认在基线生命周期成立后，Host 通用框架的主路径控制面与数据面也成立。

这样分层的原因是：如果直接跑 iperf 验证失败，问题可能来自 Host 通用框架生命周期、transport bring-up、事件链路、SoftAP 控制、或者数据面本身；先用 baseline validation 把前半段路径单独验证掉，定位会更快。

**当前阶段的结论边界**：

- `host_framework_validation` 通过，说明当前 ESP host 验证平台上的 Host 通用框架基线生命周期路径可用。
- `host_framework_iperf_validation` 通过，说明当前 ESP host 验证平台上的 Host 通用框架主路径控制面与数据面可用。
- 两个样例都通过，才可以判定 **当前 ESP host 验证平台上的 Host 通用框架可用性已经得到证明**。
- 这个结论仅对“当前 ESP host 验证平台 + 当前 transport 配置 + 当前验证样例”成立，不自动外推到所有 ESP host 或非 ESP host port。

**验收清单**：

| 测试项 | 方法 | 通过标准 |
|--------|------|---------|
| 编译 | `idf.py set-target esp32p4 && idf.py build` host 示例 | 零错误零警告 |
| SoftAP 启动 | `h_wifi_init` → `h_wifi_set_mode(AP)` → `h_wifi_set_config` → `h_wifi_start` | STA 设备可见 AP 热点 |
| STA 连接事件 | 手机/PC 连接 AP | `H_EVENT_WIFI_AP_STACONNECTED` 回调触发 |
| TCP 吞吐量 | `iperf -s` (host) + `iperf -c` (STA) | ≥ 重构前水平 × 95% |
| UDP 吞吐量 | `iperf -s -u` (host) + `iperf -c -u` (STA) | ≥ 重构前水平 × 95% |
| 运行稳定性 | iperf 持续 10 分钟 | 零 crash、零断开 |
| 重启恢复 | host 重启 → `h_hosted_init()` 再次初始化 | AP 重新可见，iperf 恢复正常 |

**与当前两个验证样例的映射关系**：

| 验证样例 | 主要回答的问题 | 通过后可以下的结论 |
|--------|------|---------|
| `host_framework_validation` | Host 通用框架生命周期、事件链路、connect/deinit 循环是否可靠 | 当前 ESP host 验证平台的 Host 通用框架基线生命周期路径可用 |
| `host_framework_iperf_validation` | Host 通用框架在 SoftAP + TCP/UDP 真实数据面场景下是否可用 | 当前 ESP host 验证平台的 Host 通用框架主路径控制面与数据面可用 |

这两个样例是前后衔接的验证阶梯，而不是互相替代的关系。

**新平台移植验证流程**：

```
1. 实现新 port (h_osal_contract_t + h_event_contract_t + h_transport_contract_t 填充 + h_port_config.h)
2. CI Tier 2 自动通过 (Linux mock 不感知平台)
3. 在新平台真实硬件上运行 Tier 3 硬件验收清单
4. TCP/UDP 吞吐量 ≥ 对应传输模式的预期值
```

### 测试框架选型

采用 [Unity](https://github.com/ThrowTheSwitch/Unity)（纯 C、单头文件 + 单源文件、嵌入式友好、无外部依赖）：

```c
// tests/test_rpc_core.c 示例
#include "unity.h"
#include "h_rpc_core.h"
#include "h_test_only.h"

void test_rpc_request_response_match(void) {
    // 注入 mock slave 的 protobuf 响应
    uint8_t mock_response[] = { /* protobuf 编码的 GetMacAddress 响应 */ };

    h_err_t ret = h_rpc_core_dispatch(mock_response, sizeof(mock_response));
    TEST_ASSERT_EQUAL(H_OK, ret);
}

void test_rpc_request_timeout(void) {
    // 不发响应 → 应超时
    h_err_t ret = h_rpc_send_request(/* ... */, 100); // 100ms 超时
    TEST_ASSERT_EQUAL(H_ERR_TIMEOUT, ret);
}
```

Mock 策略选择：
- **OSAL / 事件 / 日志层**：直接测试 port 实现（如 Linux mock 用 `pthread`），不需额外 mock
- **Transport HAL 层**：手动编写测试桩（函数指针指向测试用例内定义的 `static int mock_spi_transfer(...)`）
- **不需要 CMock**：mock 对象数量少（每个测试只 mock 1-2 个接口），手动编写测试桩比引入 CMock 更可控

## 上游同步策略

本架构采用 **Fork + 独立维护** 模式与上游官方仓库共存。

### 同步机制

```
espressif/esp-hosted-mcu (上游)
        ↓ 定期 sync / cherry-pick
  felix/esp-hosted-mcu (本 Fork)
        ├── host/core/        ← 平台无关核心层（手动维护，禁止 ESP-IDF 依赖）
        ├── host/port/        ← 移植层
        │   ├── include/      ← 移植接口契约
        │   ├── esp-idf/      ← ESP-IDF 适配
        │   ├── zephyr/       ← Zephyr 适配
        │   └── ...
        └── common/           ← 与上游共享（proto, mempool, transport header）
```

### 不同场景的处理方式

| 上游更新类型 | 影响范围 | 处理方式 |
|-------------|---------|---------|
| RPC 核心逻辑修复 | `host/core/` | 直接 cherry-pick，port 层不受影响 |
| Wi-Fi API 新增 | `host/core/` | cherry-pick 后检查是否需扩展 `h_osal_contract_t` 接口 |
| ESP-IDF 适配更新 | `host/port/esp-idf/` | 直接 cherry-pick |
| protobuf 定义变更 | `common/proto/` | 同步后重新生成 pb-c 代码 |
| 新增功能引入 ESP-IDF 依赖到 core | `host/core/` | **拒绝直接合并**，需先抽象为 port 接口 |

### 防护措施

在 CI 中增加检查，确保核心层不引入 ESP-IDF 依赖：

```bash
#!/bin/bash
# scripts/check_core_isolation.sh

# 核心层禁止出现任何 ESP-IDF 特有类型、头文件、日志宏
FORBIDDEN=$(grep -rn '#include.*esp_' host/core/ --include="*.c" --include="*.h" || true)
FORBIDDEN+=$(grep -rn 'esp_err_t\|esp_event_base_t\|esp_mac_type_t\|ESP_LOG[IEWDV]' host/core/ --include="*.c" --include="*.h" || true)
FORBIDDEN+=$(grep -rn 'wifi_init_config_t\|wifi_config_t\|wifi_ap_record_t\|wifi_scan_config_t' host/core/ --include="*.c" --include="*.h" || true)
# 禁止直接调用 FreeRTOS API
FORBIDDEN+=$(grep -rn 'vTaskDelay\|xQueueCreate\|xSemaphoreCreate' host/core/ --include="*.c" --include="*.h" || true)
# 禁止直接调用 heap_caps_malloc
FORBIDDEN+=$(grep -rn 'heap_caps_malloc\|heap_caps_free\|heap_caps_get' host/core/ --include="*.c" --include="*.h" || true)

if [ -n "$FORBIDDEN" ]; then
    echo "ERROR: ESP-IDF dependencies found in host/core/:"
    echo "$FORBIDDEN"
    exit 1
fi

echo "OK: host/core/ is ESP-IDF-free"
```

## 风险与注意事项

1. **Wi-Fi 数据结构**：已由 `h_wifi_types.h` 策略解决——核心层定义平台无关类型，protobuf RPC 层负责与 ESP-IDF 类型互转。字段布局需与 ESP-IDF 保持兼容，否则 ESP-IDF port 需做字段级映射。
2. **私有 TLV 协议**：`esp_private/wifi.h` 中的握手协议已抽象为 `h_priv_event.h`。新增 slave 芯片类型时，`h_priv_event.h` 中的芯片常量表需要同步更新。
3. **protobuf-c**：`common/proto/esp_hosted_rpc.pb-c.c` 目前使用 `protobuf-c` 生成，依赖标准 C 库，无需修改。
4. **Endianness**：核心层已经处理了大端/小端问题（protobuf 负责 RPC，hosted header 是纯字节）。
5. **中断上下文**：OSAL 合约已补充 `enter_critical` / `exit_critical`（临界区保护）和带 `isr_ctx` 参数的 `sem_give_from_isr`（解决 FreeRTOS `xSemaphoreGiveFromISR` 需要 `pxHigherPriorityTaskWoken` 的问题）。`isr_ctx` 参数允许 port 层传递平台特定的 ISR 上下文，核心层不解析其内容。但后续仍需补充：
   - `h_queue_send_from_isr()` / `h_queue_recv_from_isr()`
   - 更多 ISR 安全标志传递机制
6. **传输驱动 OS 泄漏**：当前 `sdio_drv.c`、`uart_drv.c`、`spi_hd_drv.c` 中仍有 6 处 `vTaskDelay` 直接调用。重构时必须替换为 `h_msleep()`。
7. **线程配置来源**：`sdkconfig.h` 提供的 stack/priority 配置需迁移到 `h_port_config.h`，各 port 层自行定义默认值。
