# 24. Host 框架第三方平台移植指南 (Universal Porting Guide)

## 1. 概述

ESP-Hosted Host 框架已实现 **Milestone D (独立体)**。这意味着核心逻辑 (`host/core/`) 和通用 API (`host/core/include/h_public/`) 已经与 ESP-IDF 平台完全解耦。

移植者只需在目标平台（如 STM32, Zephyr, RT-Thread 或 Bare Metal）上实现 `host/port/include/h_port_contract.h` 中定义的 **三大合约 (Contracts)**，即可运行全功能的 Wi-Fi 控制和数据面。

## 2. 移植核心步骤

### 2.1 包含路径设置
新平台的编译系统应包含以下目录：
*   `host/core/include/h_public/`: 公共 API (h_wifi_api.h, h_event.h)。
*   `host/core/include/h_internal/`: 内部核心头文件。
*   `host/port/include/`: 合约定义 (h_port_contract.h) 和包装宏 (h_wrapper.h)。
*   `common/proto/`: Protobuf 定义。
*   `common/protobuf-c/`: Protobuf-C 运行库。

### 2.2 实现三大合约 (Contracts)

你需要在你的 port 目录下创建 `const` 全局实例：

#### A. OSAL 合约 (`g_h_osal`)
负责内存、线程、互斥锁、信号量、定时器和日志。
*   **关键点**：确保 `malloc_align` 能提供 DMA 可用的对齐内存。
*   **关键点**：`sem_give_from_isr` 必须在中断上下文中安全执行。

#### B. Event 合约 (`g_h_event`)
负责事件的分发与订阅。
*   **关键点**：核心层会调用 `post` 发布 Wi-Fi/Hosted 事件。
*   **关键点**：应用层通过 `register_handler` 订阅这些事件。

#### C. Transport 合约 (`g_h_transport`)
负责物理总线 (SPI/SDIO/UART) 的数据收发。
*   **关键点**：实现 `transmit` 函数，将带 Hosted Header 的数据包发送给从机。
*   **关键点**：实现 `init` 初始化硬件外设。

### 2.3 定义平台配置 (`h_port_config.h`)
在你的 port 目录下创建此文件，定义：
*   `H_TRANSPORT_IN_USE`: 选择 `H_TRANSPORT_SPI`, `H_TRANSPORT_SDIO` 等。
*   `H_DEFAULT_TASK_STACK`: 默认任务栈大小。
*   `H_PORT_NAME`: 你的平台名称（如 "stm32-freertos"）。

## 3. 应用层接入

移植完成后，你的 `main.c` 应该像这样：

```c
#include "h_public/h_init.h"
#include "h_public/h_wifi_api.h"
#include "h_public/h_event.h"

void app_main() {
    // 1. 系统初始化
    h_hosted_init();

    // 2. 注册事件回调
    h_event_register(H_EVENT_WIFI, H_EVENT_WIFI_STA_CONNECTED, wifi_cb, NULL);

    // 3. 启动连接
    h_connect_to_slave();

    h_wifi_config_t cfg = { ... };
    h_wifi_set_config(H_WIFI_IF_STA, &cfg);
    h_wifi_connect();
}
```

## 4. 验证清单

- [ ] `h_hosted_init()` 返回 `H_OK`。
- [ ] 串口日志输出 "INIT: All required vtable slots filled"。
- [ ] 收到 `H_EVENT_HOSTED_CP_INIT` 事件（表明从机已就绪并完成握手）。
- [ ] 能成功调用 `h_get_fw_version()` 并获取正确的从机版本。
