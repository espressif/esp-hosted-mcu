# 21. Host 通用框架最终收口方案

## 1. 现状评估

当前 Host 通用框架处于 **Milestone C (过渡态/桥接完成)**。
- **成就**: `host/core/src/` 基本完成去 ESP 化，公共类型已收口，Linux mock 已能跑通大部分生产路径。
- **遗留问题**:
    - `h_serial_if.c` 仍桥接至 legacy `transport_pserial_*` 接口。
    - `h_transport_drv.c` 仍存在少量对 legacy 宏或 `g_h.funcs` 的间接依赖。
    - 控制面逻辑虽然集中，但尚未完全基于 contract 独立运行。

## 2. 终态目标：Milestone D (完整体/独立完成)

- **核心层独立**: `host/core/` 100% 通过隔离检查，且不依赖任何 `extern` 的 legacy 符号。
- **合约驱动**: 所有平台能力（含控制面传输）均通过 `h_port_contract.h` 定义的合约获取。
- **无感移植**: 新平台只需实现 contract 实例，无需修改 core 层代码。

## 3. 实施计划

### 3.1 控制面收口 (h_serial_if.c)

**目标**: 移除对 `transport_pserial_*` 的 extern 依赖。

**方案**:
1.  **重构 h_serial_if.c**:
    - 将 `transport_pserial_open/close/send/read` 替换为内部 `serial_drv_*` 和 `rpc_platform_*` 调用，这些最终由 `serial_ll_if.c` 实现。
    - 在 `h_serial_if.c` 内部实现 TLV (Type-Length-Value) 编解码，确保控制面数据格式与 Slave 保持一致。

### 3.2 传输层收口 (h_transport_drv.c)

**目标**: 移除剩余 legacy 依赖，实现 100% 隔离。

**方案**:
1.  **清理宏与包含**: 移除 `port_esp_hosted_host_config.h` 等平台头文件。
2.  **标准化常量**: 统一传输 buffer 大小（如 1600 字节）并使用 `h_` 风格的错误码。

### 3.3 核心层内存管理标准化

**目标**: 统一使用 `h_malloc`, `h_calloc`, `h_free`。

**方案**:
1.  在 `h_rpc_core.c` 和 `h_transport_drv.c` 中替换所有 `HOSTED_CALLOC` 和 `HOSTED_FREE`。

## 4. 验收标准 (Milestone D)

1.  `scripts/check_core_isolation.sh` 100% 通过。
2.  `scripts/run_linux_mock_tests.sh` 100% 通过 (ASAN/TSAN clean)。
3.  `host/core/src/` 下不再出现任何 legacy 符号 (如 `ESP_LOG*`, `esp_*` 系统调用, `g_h.funcs` 等)。
4.  GitHub CI `.github/workflows/host-core-test.yml` 全部通过 (包含多平台编译验证)。

## 5. 实施结果 (2026-05-20)

- **核心层解耦**: `h_transport_drv.c` 已完全移除 legacy 头文件，所有总线操作、上电协商和功耗管理逻辑均通过 `h_transport` 和 `h_osal` 合约实现。
- **合约扩展**: 在 `h_port_contract.h` 中新增了 `transmit` 和 `bus_ready` 总线合约，以及 `ps_init` 和 `woke_from_ps` OSAL 扩展。
- **CI 修复**: 修正了 CI 工作流中的包含路径和工具链配置，确保所有核心文件和 port 文件均能通过语法检查。
- **验证状态**:
    - `check_core_isolation.sh`: 13/13 100% 隔离。
    - `run_linux_mock_tests.sh`: 28/28 测试通过，内存与线程检查正常。
