## 目标

让 `host/core/src/` 下所有主路径文件通过统一的 portable 隔离检查，不再依赖 `port_esp_hosted_host_*` 头文件、ESP 日志宏、`ESP_ERROR_CHECK` 与 ESP-IDF 私有头。完成后核心目录边界与目录命名一致：`host/core/` 即真正意义上的核心层，所有平台耦合在 `host/port/<platform>/` 内闭环。

## 范围

### 在范围内（按 9 号路线图 WP 3.1–3.6，按文件分组）

- WP 3.1 — `h_init.c` / `h_api.c` 完全转入 portable 集合，移除所有过渡兼容
- WP 3.2 — `h_event.c` / `h_serial_if.c` 收尾，对齐 portable 隔离脚本
- WP 3.3 — `h_rpc_core.c` portable 化（**注意**：本 WP 只完成 portable 化，**不**取消 `H_BUILD_TESTS` 测试专用分支；后者属于门槛 4 WP 4.5）
- WP 3.4 — `h_rpc_req.c` / `h_rpc_rsp.c` / `h_rpc_evt.c` 去 ESP 依赖
- WP 3.5 — `h_transport_util.c` 去平台耦合
- WP 3.6 — `h_transport_drv.c`（约 955 行）独立处理：拆分平台相关初始化、迁移日志宏、抽出 GPIO/IRQ 路径到 port

### 不在范围内

- 不动 `h_wifi_types.h` 等公共类型 —— 那是门槛 2 的范围
- 不取消 `h_rpc_core.c` 在 mock 中的 `H_BUILD_TESTS` 分支 —— 那是门槛 4 WP 4.5 的范围
- 不引入第二非 ESP 平台 —— 那是门槛 5 的范围
- 本骨架版**不**展开 step 级命令、文件级替换块、TDD 步骤；这些将在扩写阶段补齐

## 依赖

- **强依赖**：门槛 2（公共类型收口）必须先完成。原因：`h_rpc_*.c` / `h_api.c` 等文件中的字段访问大量依赖 `h_wifi_*_t`，若类型主权未回收，迁移这些文件时无法稳定地走 portable 路径
- **建议先行**：门槛 1（口径统一）—— 验收语言依赖统一口径
- **可并行**：门槛 4 中**与本门槛无文件冲突**的 mock 覆盖扩展子项可并行准备脚本，但实际纳入新文件需等本门槛对应文件 portable 化完成

## 入口条件

- 门槛 2 已完成：`h_wifi_types.h` 已收口、port 层 native↔portable 适配可用、相关编译期断言生效
- 门槛 1 的口径文档已存在
- 主分支当前状态下 `host/core/src/` 各文件的 ESP 依赖盘点（即 9 号路线图所列文件清单）仍准确

## 出口条件 / 验收

参照 9 号路线图门槛 3 的验收口径：

- [ ] `host/core/src/` 下全部主路径 `.c` 文件通过 `scripts/check_core_isolation.sh`，无白名单豁免
- [ ] isolation 脚本的 `PHASE1_SCOPE` 扩展为覆盖整个 `host/core/src/` 与 `host/core/include/`
- [ ] ESP-IDF 构建在主流 sdkconfig 下通过，控制面 / 数据面 / RPC 路径无回归
- [ ] Linux mock 编译矩阵能在不靠 `H_BUILD_TESTS` 测试专用分支的前提下编译 `h_init.c` / `h_api.c` / `h_event.c` / `h_serial_if.c` / `h_rpc_req.c` / `h_rpc_rsp.c` / `h_rpc_evt.c` / `h_transport_util.c`（`h_rpc_core.c` 仍允许保留 `H_BUILD_TESTS`，留给门槛 4 WP 4.5）
- [ ] `host/core/` 内不再 `#include "port_esp_hosted_host_*.h"`

## 已知风险

1. **`h_transport_drv.c` 体量**：单文件约 955 行，带 GPIO / IRQ / 队列 / 日志多重平台耦合。简单"替换头文件"无法收口，需要做模块级拆分；存在工作量低估风险
2. **RPC 路径回归面广**：`h_rpc_*.c` 涉及序列化、命令分发、事件分发，迁移时一旦字段错位很难在编译期暴露，必须靠门槛 4 的 mock 覆盖与 ESP-IDF 真机回归共同兜底
3. **历史日志宏的语义差异**：`ESP_LOGx` 与 portable `H_LOGx` 在级别、tag、行为（早期日志 vs 普通日志）上不完全一一对应；批量替换可能造成日志可观测性回退
4. **隐式 FreeRTOS 假设**：部分代码可能隐式依赖 FreeRTOS 任务调度语义（如 yield、tick），抽到 OSAL 后行为可能微妙变化
